# Android 拼音九键技术 Spike 计划

> 状态：Open-source baseline reproduced; touch spike next  
> 日期：2026-08-24  
> 范围：只验证拼音九键技术实现路径

## 1. 唯一目标

确定我们是否能使用许可证可接受的开源输入引擎，在 Android 上开发出可日常验证的触屏拼音九键键盘。

Spike 成功不代表完整 Spoken Mobile 已经成立，只代表最关键的文字输入技术风险已经解除。

## 2. 本阶段不做

- 语音识别；
- 语音入口；
- 语音与文字融合；
- AI 后处理；
- Spoken 最终视觉设计；
- 账号、同步、剪贴板和主题；
- 对现有移动端语音原型进行增量改造。

## 3. 复用优先策略

实施顺序遵守：

```text
直接运行和改造完整开源输入法
        ↓ 不满足
复用其 IME/JNI/候选等模块
        ↓ 仍不满足
自有最小 IME 壳 + librime
        ↓ 不满足
评估其他引擎
```

不能因为自建架构更整洁，就提前重写已有成熟能力。每一项自研工作都必须有“现有项目为什么不能复用”的明确记录。

### 3.1 第一候选：Fcitx5 Android 九键分支

优先尝试直接构建和实机运行 `fcitx5-android-t9-phone`，评估能够保留：

- `InputMethodService` 与 Android 输入框适配；
- Fcitx5/Rime native 构建和插件加载；
- 中文拼音、九键映射、候选和用户词库；
- composing、候选选择、展开候选和联想；
- 英文、数字、符号、删除和回车；
- 设置、数据迁移、许可证页和测试基础设施。

如果其触屏九键只需替换布局和少量交互，应直接 fork 并做减法，不另建输入法壳。

主要验证点：该分支主要面向物理九键设备，其触屏路径是否完整、代码与上游差异是否可维护、LGPL 及词库许可是否可接受。

### 3.2 第二候选：Trime

如果 Fcitx5 九键分支的触屏改造成本过高，验证 Trime：

- 直接复用 Android + librime JNI；
- 直接使用可配置触屏键盘；
- 复用 composing、候选和 schema 部署；
- 通过配置或最小代码改动形成固定拼音九键。

技术上可能复用更多，但 GPL-3.0-or-later 会影响未来分发方式。需要把“产品开放源码”作为采用该底座的前置决策，而不能以后再处理。

### 3.3 第三候选：自有壳 + librime

只有前两个完整项目都被证明确实不适合时，才建立：

```text
Android InputMethodService
        │
        ├── 最小触屏九键 UI
        ├── Kotlin/JNI Adapter
        └── librime + 许可清晰的拼音 Schema/词库
```

该路径拥有最高产品控制力，但开发量最大，是复用失败后的兜底方案，不再作为第一实现动作。

## 4. 必须实现的最小闭环

### 4.1 IME 壳

- 可安装并在 Android 系统中启用；
- 可设为当前输入法；
- 能正确接收和释放 `InputConnection`；
- 在普通文本、聊天、搜索、数字和密码输入框中启动合适布局；
- 输入框切换后不保留旧 composing。

### 4.2 拼音九键

- `ABC / DEF / GHI / JKL / MNO / PQRS / TUV / WXYZ`；
- 数字序列转换为可读拼音 preedit；
- 显示音节边界；
- 九键歧义消解；
- 显式分词；
- 删除一个编码、清空当前 composing；
- 选择、确认和翻页候选；
- 候选展开面板。

### 4.3 中文候选

- 单字、词组和整句候选；
- 第一候选稳定；
- 用户选择后正确提交或继续 composing；
- 基础用户词频学习；
- 删除与回退不会破坏输入框正文；
- 重新打开键盘后用户词频仍存在。

### 4.4 辅助输入

- 中文高频标点；
- 最小英文 QWERTY；
- 数字面板；
- 基础符号面板；
- 删除、空格、回车、发送、搜索和完成动作。

这些辅助布局只需达到完成测试任务的程度，不做完整产品体验。

## 5. 实施步骤

### Step 0：开源底座复现

- clone 并固定 Fcitx5 Android 九键分支提交；
- 按其官方流程构建输入法本体和 Rime 插件；
- 在目标手机安装并完成中文九键冒烟测试；
- 记录触屏九键是否可用、需要安装几个 APK、首次词库部署方式；
- 绘制与上游 Fcitx5 Android 的差异范围；
- 若无法满足，再以相同步骤构建和实测 Trime。

输出：`OPEN_SOURCE_BASELINE_REPORT.md`，包含可复用模块、必须修改模块和明确淘汰原因。

当前结果：Fcitx5 Android 九键分支已在固定提交完成 arm64-v8a 主 APK 与 Rime 插件构建，735 个单元测试全部通过。其触屏 T9 只有功能条、没有 3×3 数字键，因此选为引擎/会话基线，下一步只补触摸九键与语义适配。详见 `OPEN_SOURCE_BASELINE_REPORT.md`。

### Step 1：依赖与许可证锁定

- 固定 librime 版本与源码提交；
- 选择最小拼音 Schema 和词库；
- 为代码、Schema、词库、OpenCC 和 native 依赖建立 SPDX 清单；
- 排除许可证不能接受的语言模型和词库。

输出：`THIRD_PARTY_SPIKE.md`。

### Step 2：确定最小改造面

优先在选中的完整开源底座中实现固定拼音九键。只有底座评估明确选择“自有壳 + librime”时，才执行以下 native/JNI 自建步骤。

### Step 3：Native 可运行性（仅自有壳路线）

- 使用 Android NDK 构建 arm64-v8a librime；
- 在普通 Android 测试 Activity 中初始化引擎；
- 创建 session、发送按键、读取 preedit 与候选；
- 重复创建/销毁 session，检查 native 崩溃和内存释放。

通过后再进入 IME，避免同时调试 native 和输入法生命周期。

### Step 4：最小 InputMethodService（仅自有壳路线）

- 新建独立 Spike App/模块；
- 使用简单 View 或 Compose 构建固定九键；
- 将候选提交到当前 `InputConnection`；
- 处理 `onStartInput`、`onFinishInput` 和服务销毁；
- 每个输入连接使用独立逻辑 session。

### Step 5：九键 composing

- 数字键映射到 T9 拼音；
- 展示拼音 preedit 和音节边界；
- 实现删除、清空、分词和确定；
- 验证能否实现显式拼音消歧；
- 若 librime 无法暴露所需状态，记录缺口并评估自有适配层成本。

### Step 6：候选体验

- 横向首屏候选；
- 展开候选；
- 候选翻页；
- 选择后继续组句；
- 用户词频持久化；
- 与当前豆包九键执行相同输入语料对比。

### Step 7：辅助布局与输入框

- 最小英文、数字、符号；
- 密码、电话、邮箱、网址、搜索和聊天输入框；
- 验证回车 action；
- 验证隐藏、旋转、切 App 和重新聚焦。

### Step 8：实机结论

- 运行固定测试语料；
- 连续真实使用 3–7 天；
- 记录候选失败、误触、删改困难、崩溃和性能问题；
- 给出 Go / Conditional Go / No-Go 结论。

## 6. 验收语料

至少覆盖：

- 常用短句；
- 长句连续组词；
- 多种音节切分可能的句子；
- 人名、地名、产品名；
- 中英文混合；
- 数字、日期、时间、金额；
- 连续删除和重新输入；
- 同一拼音的多候选选择；
- 用户词频经过重复选择后的排序变化。

正式开发前补充一份来自用户真实输入习惯、已脱敏的 30–50 条测试语料。

## 7. Go 条件

- 30–50 条真实语料全部可以完成输入；
- 拼音 preedit、分词、消歧、删除和候选选择可理解且稳定；
- 候选质量达到可连续使用验证的水平；
- 用户词频可以持久学习；
- 输入框切换不串 composing；
- 无阻断性 native 崩溃和资源泄漏；
- 普通设备候选首屏 P95 目标小于 50 ms；
- 代码、Schema 和词库许可证路径清晰可接受；
- 不依赖与产品开源/分发策略冲突的许可证；若选择 GPL 底座，已明确接受相应开源义务。
- 对于选择的底座，能够明确列出复用比例、长期同步上游方式和必须维护的补丁面。

## 8. No-Go 条件

- librime 无法支持可用的九键歧义消解；
- 只能获得黑盒候选，无法可靠处理 preedit、分词和删改；
- 候选质量在真实语料中明显不可用；
- 必须依赖许可证不可接受的词库或模型；
- JNI/native 稳定性无法达到 IME 常驻进程要求；
- 修补成本接近自行开发完整拼音引擎；
- 输入延迟或资源占用不适合默认输入法。

## 9. 最终交付物

- 可安装的独立九键 Spike APK；
- 开源底座复现与差异报告；
- Spike 源码与构建说明；
- 第三方依赖和许可证清单；
- 固定测试语料及结果；
- 性能与稳定性记录；
- 与豆包当前九键的任务级差异记录；
- 明确的技术 Go / No-Go 报告；
- 若 No-Go，下一候选路径及失败原因。

## 10. 决策闸门

在 Go 结论前：

- 不设计 Spoken 最终语音入口；
- 不决定语音与文字融合状态；
- 不构建完整移动端产品；
- 不在现有语音原型上继续堆叠功能。

只有九键技术路径验证成立后，才进入下一轮产品功能与融合设计。

## 11. 自研准入规则

以下能力默认禁止从零开发，除非底座评估报告证明无法复用：

- Android IME 生命周期；
- librime/Fcitx5 native 构建；
- JNI 基础会话封装；
- 拼音解码；
- 候选分页与选择模型；
- 用户词频持久化；
- 英文、数字和符号基础布局；
- `EditorInfo` 与回车动作适配；
- composing 删除和提交语义；
- 第三方许可证展示。

Spoken 在 Spike 阶段只开发开源底座缺失的触屏九键差异，不主动重写成熟通用能力。
