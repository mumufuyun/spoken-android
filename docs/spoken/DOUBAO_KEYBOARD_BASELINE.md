# 豆包输入法九键基线拆解

> 日期：2026-08-24  
> 来源：用户当前实际使用截图  
> 用途：理解成熟拼音九键的输入机制，不代表 Spoken 最终产品方案

## 0. 使用边界

本文件是竞品观察记录，不是 Spoken 的设计规范。

当前只提取与“拼音九键能否实现”直接相关的内容：按键映射、拼音 composing、音节消歧、候选、分词、删改、英文/数字/符号布局。豆包的语音入口位置、录音状态和语音文字融合方式仅作为观察，不进入当前技术 Spike 的需求和验收标准。

Spoken 最终如何融合语音与文字，需要在九键技术路径验证通过后重新进行产品讨论。

## 1. 已获得的界面状态

1. 中文拼音九键常态；
2. 数字面板；
3. 英文 QWERTY 面板；
4. 符号面板；
5. 拼音 composing 与候选栏；
6. 语音录制状态。

当前仍缺少：

- 候选面板展开；
- 已选部分词组后的修改状态；
- 语音识别中和完成后的状态；
- 密码、邮箱、网址和验证码输入框状态。

## 2. 整体结构

豆包键盘不是“语音页”和“文字页”二选一，而是把语音入口长期嵌入文字键盘。

常态从上到下可以拆成：

```text
功能条：快捷入口 / 「点击说话」语音胶囊 / 收起键盘
主键区：当前文字布局
底部模式区：符号、数字、语音、中英文、回车等
```

这只是豆包当前的信息架构，不构成 Spoken 的融合方案结论。

## 3. 中文拼音九键布局

### 3.1 中央九键

```text
@#    ABC   DEF
GHI   JKL   MNO
PQRS  TUV   WXYZ
```

观察：

- 中文常态不显示数字，减少视觉噪音；
- `@#` 占据传统数字 1 的位置；
- 其余字母组符合标准手机九键肌肉记忆；
- 按键面积明显大于英文全键，适合拇指输入。

### 3.2 左侧高频标点栏

主九键左侧固定一列：

- `，`
- `。`
- `？`
- `！`

底部为“符号”。

这使中文高频标点保持一击可达，不需要打开符号面板。Spoken 原型应保留这一结构进行对照验证。

### 3.3 右侧编辑动作栏

右侧固定一列：

- 删除；
- 重输；
- 换行。

其中“重输”是九键特有的高价值动作，推测用于清空或回退当前拼音组合。需要通过实际操作确认其精确语义，再决定是复刻、拆成 composing 清除，还是使用其他交互。

### 3.4 底部模式区

从左到右：

- 符号；
- `123`；
- 宽语音键；
- 中/英切换；
- 右侧动作栏延续的换行键。

宽语音键位于传统空格区域，意味着语音是主操作而不是工具栏附属功能。中文九键常态没有独立大空格键。

## 4. 数字面板

数字面板保留三列数字网格：

```text
1 2 3
4 5 6
7 8 9
返回 0 .
```

同时具备：

- 左侧 `% + - *` 运算符栏；
- 右侧删除、空格、换行；
- 顶部一行常用符号快捷入口；
- 左下角进入完整符号面板。

设计含义：数字布局不是只有 0–9，而是针对真实数字和计算输入补充小数点、运算符、空格及回车。

## 5. 拼音 composing 与候选

拼音输入后，键盘顶部出现两个独立层级：

```text
preedit：ni'shi'shui
候选栏：你是谁｜尼是谁｜你是｜密室｜迷…｜展开
```

观察：

- preedit 使用可读拼音并以 `'` 显示音节边界，而不是只显示九键数字序列；
- 第一候选使用蓝色高亮，形成明确的默认提交目标；
- 候选栏右侧有向下箭头进入展开候选面板；
- 候选不仅包含完整句，也包含较短词组，允许用户改变分段；
- composing 状态下，右侧动作为删除、重输、确定；
- `@#` 键动态变为“分词”，说明九键输入需要显式处理音节边界；
- 左侧栏由高频标点动态切换为 `mi / ni / o / m` 等拼音消歧选项。

最后一点尤其重要：豆包并不是只依赖候选排序解决九键数字歧义，而是在主键区旁提供可直接选择的拼音分支。Spoken 的 T9 原型必须验证 `librime` 是否能暴露足够的拼音状态来实现这种消歧交互。

需要进一步确认：左侧分支是针对当前最后一次按键、当前音节，还是整个输入串；选择后如何移动到其他音节继续修改。

## 6. 英文面板

英文使用 QWERTY，而不是英文 T9：

- 三排小写字母；
- Shift 和删除位于第三排两端；
- 底部包含 `123`、标点、宽语音键、中/英切换和换行；
- 顶部仍保留“点击说话”语音胶囊。

因此 Spoken MVP 应将“中文九键 + 英文 QWERTY”设为首发组合，不需要优先开发英文 T9。

## 7. 符号面板

符号面板由三部分构成：

- 顶部最近或常用符号横栏；
- 中部三行符号网格；
- 底部符号分类导航。

底部分类包含历史、中文、英文、括号、货币、数字等入口，并提供醒目的返回键。它说明符号面板需要记忆最近使用，而不是单一静态字符表。

## 8. 对 Spoken 九键 Spike 的直接约束

### 8.1 原型需要验证的九键结构

- 中央 3×3 拼音九键；
- 左侧栏在空闲时显示中文高频标点，在 composing 时显示拼音消歧分支；
- 右侧删除、重输/清除 composing、回车动作栏；
- 独立的 preedit 行和横向候选栏；
- 候选栏展开入口；
- composing 时将 `@#` 动态替换为“分词”；
- 中文九键与英文 QWERTY 分离；
- 独立数字和符号面板；
- 正确适配输入框的删除、确认和回车动作。

### 8.2 Spike A 明确不验证的部分

- 任何语音入口、录音状态或语音转写；
- 语音与文字键盘如何融合；
- Spoken 最终键盘的信息架构和视觉设计；
- 符号面板首版只实现中文高频、英文和数字三组；
- 暂不实现最近符号学习；
- 暂不实现视觉主题和动画。

### 8.3 不能在原型中省略的部分

- 删除未完成编码和删除正文必须是两个正确阶段；
- “重输”的精确替代行为；
- 拼音音节边界显示和分词；
- 左侧拼音消歧分支；
- 候选选择、展开和翻页；
- 数字、英文、符号进入后可以一击返回中文九键；
- 回车键随输入框显示换行、发送、搜索、完成等正确语义；
- 密码和验证码输入框切换到安全、合适的布局。

## 9. 语音录制状态

开始录音后，键盘没有切换到独立全屏语音页，九键布局仍完整保留，但操作语义发生变化：

- 顶部常态功能条被居中的“正在倾听 点击结束”及动态波形替代；
- 底部宽语音键显示“轻触结束”，确认停止是单击行为；
- 右下角由“换行”变为“确定”；
- 删除、重输、中英、数字、符号和九键仍然可见；
- 截图中尚未出现实时转写正文，不能确定转写将占用 preedit 行还是候选栏。

这说明豆包将语音设计成九键之上的临时会话状态，但 Spoken 是否采用同样模型尚未决定。

需要实机验证录音期间其他文字键是否仍可点击，以及点击“确定”“重输”分别处理录音还是文字 composing。

## 10. 需要用户补充确认的问题

1. “重输”是清除整段未完成拼音，还是回退到重新选择候选？
2. 录音前，顶部“点击说话”和底部波形键是否都会启动同一种录音？
3. 底部波形键长按是否有独立行为？
4. 拼音候选栏如何展开、翻页和返回？
5. 左侧拼音分支作用于当前音节还是整个输入串？
6. 录音过程中九键、删除、重输和“确定”是否仍可操作？
7. 是否经常使用左侧四个标点和右侧“重输”？

## 11. 当前设计判断

对当前九键技术 Spike 有价值的是前四点；第五点只记录竞品语音形态，不作为要求：

1. 九键中央输入区保持稳定，模式变化主要发生在两侧动作栏和底部模式区；
2. 左侧栏是动态上下文区域：空闲时输入标点，composing 时承担拼音消歧；
3. 中文九键采用独立“分词”和“重输”，而不是照搬全键盘逻辑；
4. preedit、候选与展开入口分层清晰，九键歧义既通过候选排序也通过显式拼音分支解决；
5. 语音入口同时存在于功能条和底部核心键区，录音时仍保留九键布局，说明语音是文字键盘上的会话状态。

Spoken 是否沿用任何豆包信息架构，待九键技术验证通过后再讨论。
